# Cloudflare WARP 智能分流控制台

> 国际流量走 Cloudflare WARP 加密出口，国内流量直连 —— 一个零依赖、可视化的 Windows 流量分流工具。

![status](https://img.shields.io/badge/python-3.8%2B-blue) ![license](https://img.shields.io/badge/license-MIT-green) ![platform](https://img.shields.io/badge/platform-Windows-0078D4)

---

## 一、它能做什么

- 🌍 **国际流量走 WARP**：访问境外网站 / 服务时，流量经 Cloudflare WARP 隧道加密出口。
- 🏠 **国内流量直连**：中国大陆 IP 走本地网络直连，不绕路、不掉速、不影响国内视频 / 游戏 / 网银。
- 🖥️ **可视化控制台**：浏览器打开即看状态、出口 IP、已注入规则数，一键开关。
- 🔘 **一键开关 / 一键还原**：随时启用、停用；任何异常点「一键还原」立刻回到干净网络状态。
- 🩺 **分流自检**：一键验证「国际是否走 WARP、国内是否直连」，不再靠猜。
- 🔧 **修复 IPv6**：解决 WARP 连接卡在 `happy eyeballs` 的问题（一键禁用适配器 IPv6）。
- 📡 **规则库自更新**：内置中国大陆 IPv4 段，可一键从 APNIC 刷新到最新；也支持**后台定时自动更新**。
- 📊 **实时速率 / 延迟面板**：国内延迟、国际延迟、下载速率、在线时长，附实时曲线图。
- 🔁 **断线自动重连守护**：后台监测 WARP 状态，意外断开自动重连（可开关）。
- 🚀 **开机自启**：通过 Windows 计划任务在登录时自动以最高权限启动（可开关）。
- 🔔 **系统托盘图标**：图标颜色反映连接状态，**单击或双击即打开控制面板**，右键菜单可快速启用 / 停用 / 修复 IPv6 / 退出。
- 🗂️ **自定义 / 多规则列表导入**：除内置中国列表外，可导入自己的 CIDR 列表（文本或 URL），自由启用 / 停用 / 删除。
- 🛡️ **网络保障（底线）**：分流是锦上添花，上网才是刚需。看门狗每 20 秒探测联网，
  连续失败即**自动逐级退让**（还原网卡 DNS → 断开 WARP 回到直连 → 强制清空 DNS）；
  另有**系统兜底计划任务**每 5 分钟巡检一次，即使程序被强杀或没启动也能兜住
  「DNS 残留导致全机断网」。控制台与托盘都有「网络急救」按钮可立即触发。
- 🌓 **暗亮主题切换**：深色 / 浅色主题，选择自动保存。
- 🏢 **Zero Trust 账号锁定提示**：检测到团队策略锁定分流时，面板顶部给出醒目提示与处理建议。

## 二、工作原理

```
                        你的电脑
┌──────────────────────────────────────────────┐
│                                                │
│   国内流量 (中国大陆 IP)  ────►  本地网关  ──────┼──► 直连（不走 WARP）
│                                                │
│   国际流量 (其余所有 IP) ──►  Cloudflare WARP   ┼──► 加密隧道 ──► Cloudflare 出口
│                          (split-tunnel 排除)   │
└──────────────────────────────────────────────┘
```

工具把 **中国 IPv4 段**加入 WARP 的 **split-tunnel 排除列表（exclude）**：

- 命中排除列表（中国大陆）→ 直连本地网络；
- 未命中（国际）→ 走 WARP 全隧道出口。

这是 WARP 官方能力，比手工改系统路由表更干净、更易还原。

### 规则是怎么写进 WARP 的（性能关键）

早期版本用 `warp-cli tunnel ip add-range` 一条一条写规则，而 WARP 的 daemon 是**串行**处理这些请求的（实测 74 ms/条），5400+ 条要 **8 分 36 秒**。更糟的是旧流程是「先把 WARP 连上，再逐条注入」——这 8 分钟里隧道已经建立、但排除列表几乎是空的，于是**包括国内流量在内的所有流量都被灌进隧道**，表现为「一注入就断网」。

现在改成两条：

1. **配置直写（秒级）**：WARP 把排除列表以明文 JSON 存在
   `C:\ProgramData\Cloudflare\settings.json` 的 `excluded_ips` 里。
   停掉 `CloudflareWARP` 服务 → 原子改写该文件 → 起服务，daemon 就按新配置加载。
   实测写入 5400+ 条耗时 **0.007 秒**。改写照抄 daemon 自带的默认排除（Apple 服务、组播、链路本地等 22 条），只替换我们自己的部分；改写前自动备份，失败自动回退逐条注入。
2. **先注入、后连接**：注入在 WARP **断开状态**下完成，此时网络是纯直连，用户在启用过程中完全无感；规则全部就位后才执行 `connect`，一步到位。

| 场景 | 旧版 | 现在 |
|---|---|---|
| 全新启用（规则为空） | 516 秒 | **约 27 秒** |
| 停用后再启用（规则已在） | 516 秒 | **约 16 秒**（仅剩 WARP 握手时间） |

另外「停用分流」现在**只断开、不清规则**（旧版会 `tunnel ip reset`），所以再次启用是秒级的。需要彻底清空请用「一键还原」。

### 两条分路：TUN 全局 / Proxy 分路（不开 TUN）

上面讲的是 **TUN 路线**。从 v1.1 起还有第二条路 —— **Proxy 分路**，在控制台「分路模式」里切换。

为什么要做第二条路：TUN 会接管系统默认路由。如果你**经常被 RDP 远程接入**，隧道一抖动，远程桌面就断在门外、人进不去。Proxy 分路一行系统路由都不改。

它不需要自己写分流桥 —— 本机 `warp-cli`（2026.6.x）原生就支持：

```
warp-cli mode proxy          # 建隧道供 SOCKS5 使用，不创建 TUN 适配器
warp-cli proxy port 40000    # 指定 SOCKS5 监听端口 127.0.0.1:40000
```

实测（`tools/test_proxy_mode.py`）：切到 proxy 模式后 **CloudflareWARP 适配器根本不存在、WARP 接口路由 0 条**，裸直连 `cdn-cgi/trace` 显示 `warp=off` —— 系统路由一行未改。

但裸 SOCKS5 **不分流**：你给浏览器配上它，国内站也要绕地球一圈。所以再叠一层本地 HTTP 分流桥 `127.0.0.1:7890`（纯 Python 标准库，已打进 exe）：目标域名解析后用同一套 5440 条 CIDR 判定，国内直连、国外走 WARP SOCKS5。

| | TUN 全局（默认） | Proxy 分路 |
|---|---|---|
| 生效范围 | 所有进程，零配置 | 仅配了代理的应用（浏览器 / git / curl） |
| 系统默认路由 | 接管 | **完全不动** |
| RDP / 局域网 | 靠 `ALWAYS_DIRECT` 保留段兜底 | **零影响** |
| UDP / QUIC / 游戏 | 支持 | 不支持（SOCKS5 只做 TCP） |
| 隧道异常的后果 | 全局断网 | 只有代理不可用，本机网络照常 |
| 分流判据 | IP 段（5440 条 CIDR） | 同一套 CIDR，域名解析后判定 |

使用方法：

1. 控制台「分路模式」切到 **Proxy 分路**，点开关启用；
2. 给应用配上代理 `127.0.0.1:7890`（HTTP）或直接用 `127.0.0.1:40000`（SOCKS5，不分流）；
   ```bash
   git config --global http.proxy http://127.0.0.1:7890
   set HTTPS_PROXY=http://127.0.0.1:7890     # cmd
   $env:HTTPS_PROXY="http://127.0.0.1:7890"  # PowerShell
   ```
3. 想让不认 SOCKS 的普通应用也走分流，打开「写入系统代理」开关（默认关）。
   局域网与 localhost 会自动写进 `ProxyOverride` 绕过，关闭时精确还原你原来的值。

已知限制：UDP 不代理（游戏 / QUIC 请切回 TUN）；分流桥是用户态 Python，适合网页 / git / 包管理器，不适合大流量下载或视频。

## 四、Cloudflare WARP 安装与配置（详细）

### 1. 下载客户端

前往 Cloudflare 官方页面下载 **Cloudflare WARP（即 1.1.1.1 客户端）** 的 Windows 版本：

- 官网入口：<https://one.one.one.one/> → 点击 **Download for Windows**
- 或 Cloudflare 产品页：<https://www.cloudflare.com/products/warp/>
- **官方直链（GA 稳定版，x64）**：<https://downloads.cloudflareclient.com/v1/download/windows/ga>

> 本仓库的 **GitHub Release** 附件里也附了一份安装包镜像，方便网络受限时
> 直接取用。但仍建议优先走官方渠道，并以官方校验值为准。

> 安装后默认路径为 `C:\Program Files\Cloudflare\Cloudflare WARP\`，包含：
> - `Cloudflare WARP.exe`（图形客户端）
> - `warp-cli.exe`（命令行工具，本工具依赖它）

### 2. 安装

双击下载的安装包，按向导一路「下一步」完成安装。安装后任务栏右下角会出现 Cloudflare WARP 图标。

### 3. 登录 / 激活（可选但建议）

- 打开 Cloudflare WARP 客户端，默认即为 **WARP** 模式。
- 点击登录可绑定免费账号（**WARP 基础模式免费，无需付费**；WARP+ 需要邀请密钥，非必需）。
- 即使是完全不登录的匿名状态，基础 WARP 模式通常也能连接。

### 4. 验证安装

以**管理员**身份打开 PowerShell，执行：

```powershell
# 查看版本（能输出版本号即说明安装成功）
warp-cli --version

# 若提示 "warp-cli 不是命令"，用完整路径：
& "C:\Program Files\Cloudflare\Cloudflare WARP\warp-cli.exe" --version

# 确认文件存在
Test-Path "C:\Program Files\Cloudflare\Cloudflare WARP\warp-cli.exe"
```

### 5. 首次注册（如连接报注册错误时）

若启用分流时 `warp-cli connect` 报错提示需要注册，请先在管理员 PowerShell 执行一次：

```powershell
warp-cli register
warp-cli connect
# 看到 "Status update: Connected" 即成功，随后可 warp-cli disconnect
```

> 本工具的 `run.bat` 会自动以管理员身份运行，并在启用时自动执行 `warp-cli --accept-tos connect`，多数情况下无需手动注册。

## 五、快速开始

两种方式，**任选其一**：

### 方式 A：免打包（推荐先用这个）

1. **双击 `run.bat`**（弹出 UAC 用户账户控制时点击「是」允许提权）。
2. 脚本会自动启动本地服务，并在浏览器打开控制台：
   ```
   http://127.0.0.1:8777/
   ```

### 方式 B：打包好的 exe（给别人用时方便）

1. 先生成一次 exe：双击 **`build.bat`**（会自动装 PyInstaller、自动提取官方图标）。
2. 之后双击根目录生成的 **`WARP-Split-Console.exe`** 即可，无需 Python 环境。

> exe 必须与 `index.html`、`china_cidr.txt` 放在**同一目录**，
> 否则找不到控制台页面和规则库。

### 启用分流

点击控制台中间的**大开关 → 启用**：
- 先连接 WARP 隧道（约 6–30 秒，偶发卡顿时自动重试）；
- 再并发注入中国大陆 IP 规则（约 5400 条，1–4 分钟，带进度条）。

启用完成后状态变为 **「分流中」**，点 **「分流自检」** 查看验证结果。

> ⚠️ 注意：**必须通过 `run.bat` 或 exe 启动**，不要直接双击 `index.html`。
> 直接以 `file://` 打开页面会导致前端连不上本地服务，点击按钮报「请求失败」。

## 六、功能说明

| 按钮 | 作用 |
|---|---|
| **大开关（启用 / 停用）** | 一键启用或停用分流。启用 = 连接 WARP + 注入国内规则；停用 = 断开 WARP + 清空规则。 |
| **刷新状态** | 立即刷新运行状态、出口 IP、规则计数。 |
| **更新中国IP列表** | 从 APNIC 重新拉取最新中国大陆 IPv4 分配，生成 `china_cidr.txt`。建议每隔一段时间点一次。 |
| **分流自检** | 只读验证：检查 WARP 是否连接、出口 IP 是否 Cloudflare、国内规则是否注入、中国 IP 是否直连、外国 IP 是否走 WARP。返回 **PASS / FAIL**。 |
| **修复IPv6** | 一键禁用 `CloudflareWARP` 虚拟适配器的 IPv6，解决连接卡在 `happy eyeballs` 的问题（可逆，可再点一次恢复）。 |
| **停用分流** | 断开 WARP 并清空分流规则，网络恢复正常。 |
| **一键还原** | 终止正在进行的操作并强制断开 + 重置，回到最干净的网络状态（紧急兜底）。 |
| **🌓 主题** | 右上角按钮切换深色 / 浅色主题，选择会持久化保存。 |

### 设置项（可持久化）

| 开关 | 默认 | 作用 |
|---|---|---|
| **开机自启** | 关 | 通过 Windows 计划任务（登录时、最高权限）自动启动本工具 |
| **断线自动重连** | 开 | 后台每 15 秒检测，若在启用状态下 WARP 断开则自动重连（只补差集规则） |

| **启动时自动恢复分流** | 关 | 关闭时：程序启动后**不会自己去连 WARP**。若上次是启用状态，面板会提示你手动点开关恢复（规则已保留在 WARP 里，恢复约 1 秒）。开启后才会在启动时自动恢复 |
| **后台自动更新规则** | 关 | 每 24 小时自动从 APNIC 拉取最新中国 IP 列表并热更新（保留已启用列表） |
| **启用速率监测** | 开 | 关闭后不再测速，减少流量占用 |
| **系统托盘图标** | 开 | 关闭后不显示托盘图标（也可用 `--no-tray` 参数启动） |
| **智能 DNS 分流** | 开 | **TUN 分路下强烈建议保持开启**。按域名分流解析，让国内站拿国内 CDN 节点（实测吞吐 2.3 倍、首包快 30 倍），境外站走公网 DNS 经隧道查询、不被污染。详见 Q2 |
| **分路模式** | TUN 全局 | 切到「Proxy 分路」可不开 TUN、不改系统路由（详见上一节） |
| **写入系统代理** | 关 | 仅 Proxy 分路下有意义：把分流桥 `127.0.0.1:7890` 写进 Windows 系统代理，局域网自动绕过，关闭时精确还原 |

### 自定义规则列表

控制台「规则列表」区域支持：

- **导入文本**：直接粘贴 CIDR，每行一条（如 `192.168.0.0/16`），命名后保存；
- **导入 URL**：填写一个返回 CIDR 列表的网址，自动拉取；
- **启用 / 停用**：每个列表可单独开关，即时生效；
- **删除**：移除不再需要的列表。

> 所有导入的列表都会与内置 `china_cidr.txt` 合并后一起注入 WARP 排除列表。
> 自定义列表存放在 `rules/` 目录（已加入 `.gitignore`，不会上传）。

### 系统托盘怎么用

| 操作 | 效果 |
|---|---|
| **单击** / **双击** 图标 | 直接打开控制面板（`http://127.0.0.1:8777/`） |
| **右键** 图标 | 弹出菜单：打开控制台 / 启用分流 / 停用分流 / 修复 IPv6 / 退出 |

图标颜色含义：

| 颜色 | 状态 |
|---|---|
| 🟢 绿色 | 分流中（WARP 已连接且规则已注入） |
| 🟠 橙色 | 操作中，或已启用但正在重连 |
| 🔴 红色 | 未启用 |

> 💡 **Windows 11 提示**：新出现的托盘图标常被自动折叠进任务栏右下角的「^」隐藏区。
> 点开「^」找到本工具图标，拖到托盘区即可常驻显示。

### 分流自检怎么看

自检会给出 5 项检查结果（绿色 ✅ / 红色 ⚠）：

- **WARP 已连接**：底层 WARP 隧道是否建立；
- **出口 IP / 归属**：你的公网出口是否落在 Cloudflare 段（说明国际流量确实走 WARP）；
- **已注入国内规则**：排除列表中的中国 IP 段数量（应为数千条）；
- **中国 IP 首跳**：访问中国 IP 的第一跳是否为你的本地网关（是 = 直连）；
- **外国 IP 首跳**：访问外国 IP 的第一跳是否为 Cloudflare（是 = 走 WARP）。

全部通过即 **PASS**，代表分流真正生效。

## 七、安卓端（手机）

手机端**不需要本工具**：安卓版 WARP（1.1.1.1 App）自带分流能力，
在 App 内配置即可达成「国内直连、国外走 WARP」。

> 📱 **完整图文步骤、排除应用清单、可导入的网段文件见
> [`android/README.md`](android/README.md)。** 本章为要点概述。

### 方案 A：排除国内应用（零门槛，推荐）

适合绝大多数人——把常用的国内 App 排除出隧道，它们的流量直连，
其余（浏览器、YouTube、X、Telegram 等）走 WARP。

1. 打开 **1.1.1.1** App
2. 右上角 **菜单（≡ 或 ⚙）→ 高级 → 连接选项**
3. 找到 **排除网络流量 / Exclude Network Traffic**
4. 选择 **应用（Apps）**，勾选你要直连的国内 App

> 菜单名称会随版本变化，找不到时用 App 内搜索找 "Exclude"。

常用国内应用包名（供核对，避免勾错）：

| 应用 | 包名 |

### 关于安卓安装包：为什么不能只给 base.apk

split_config.arm64_v8a.apk  <- 各 CPU 架构的 native .so（boringtun）
split_config.zh.apk         <- 语言资源

WARP 的 WireGuard 实现 **boringtun** 是 Rust 编写的 native 库，
位于 ABI 分包中。**只装 base.apk 会缺 .so，表现为能装但建不了隧道 /
一开就断。** 因此要么整包导出，要么直接从官方渠道安装。

仓库提供了导出脚本（手机开启 USB 调试并连线后运行）：

```powershell
python tools\export_android_app.py
```

它会 `adb pull` 全部分包到 `dist/android/`，打包成 `.apkm`
（用 **SAI** 或 **APKMirror Installer** 安装），并校验是否含 `lib/*.so`。

## 八、常见问题（FAQ）

### Q1. 点启用报 `Connecting ... happy eyeballs ...` 卡住 / 启用失败
这是 WARP 守护进程在同时探测 IPv4 / IPv6 端点，IPv6 探测卡住导致握手完不成。
**解决**：
1. 工具已内置「断开重连重试 4 次 + 重启 `CloudflareWARP` 服务兜底」，多数情况会自动恢复；
2. 若仍失败，点控制台的 **「修复IPv6」** 按钮禁用适配器 IPv6 后再启用；
3. 或在「网络连接 → CloudflareWARP 适配器 → 属性」取消 IPv6 勾选。

### Q2. 启用分流后，千兆宽带为什么跑不满？（这是 DNS 的问题，不是路由的问题）

**根因**：开了 WARP 之后，DNS 查询会经隧道出境。国内 CDN 看到的是 Cloudflare 的海外出口（`colo=LAX`），于是把你当境外用户，返回**海外节点**。

实测同一台机、同一个国内镜像、同一个文件：

| 域名被解析到 | 吞吐（8 并发） | 首包延迟 |
|---|---|---|
| 海外节点 `101.33.20.158`（新加坡） | 80 Mbps | 2.42s |
| 国内节点 `120.232.191.137` | **183 Mbps** | **0.08s** |

RTT 差 30 倍。TCP 单流吞吐上限 ≈ 窗口/RTT，所以延迟一高，带宽就上不去 —— 哪怕规则本身分得再准也没用。

典型表现（开了分流后）：

| 域名 | WARP 的 DNS 返回 | 国内 DNS 返回 |
|---|---|---|
| www.baidu.com | `103.235.46.x`（海外） | `111.45.11.x` ✅ |
| www.taobao.com | `155.102.176.x`（海外） | `120.240.158.x` ✅ |
| mirrors.cloud.tencent.com | `101.33.20.x`（新加坡） | `120.232.191.x` ✅ |

**解决办法：开「智能 DNS 分流」**（默认开启）。它在本机 `127.0.0.1:53` 起一个 DNS 代理，按域名做分流解析：国内域名用国内 DNS 拿国内节点，境外域名走公网 DNS 经隧道查询。

实现上用的是 WARP **官方的 `dns fallback` 机制**（`warp-cli dns fallback add <后缀>`），而不是去争抢网卡 DNS —— 因为 WARP 的虚拟网卡 metric 更低，改网卡 DNS 根本抢不过它（实测把 metric 调到 50 也没用）。

### Q2-0. 智能 DNS 的原理细节（为什么这么绕）
有三个反直觉的实测结论，都踩过坑：
1. WARP 的 fallback 服务器**默认不是** `127.0.0.1`，而是网卡 DHCP 学来的地址（通常是路由器）。只加后缀不改网卡 DNS 的话，查询会转给路由器，国内域名碰巧是对的，但**境外域名会被 ISP 污染**（实测 `google.com` 被解析成 `31.13.92.37`，那是 Facebook 的段）。
2. WARP 的 fallback 服务器**会跟随网卡 DNS**，但**只在网卡 DNS 是单条目时**才跟随（实测写两条 `127.0.0.1`+`223.5.5.5` 会失效退回路由器）。所以只写一条 `127.0.0.1`。
3. **境外分支绝不能填 `127.0.2.2`（WARP 自带 DNS）**，否则死循环：代理问 `127.0.2.2` 查 `google.com` → WARP 发现 `com` 命中 fallback 后缀 → 把查询转回 `127.0.0.1`（我们）→ 我们再问 `127.0.2.2` → …，实测 3.5 秒超时后只能退回被污染的国内结果。改用公网 DNS（`1.1.1.1`，经隧道出境）即可绕开。

另外 `dns fallback add/reset` 属于「设置变更」，会让 WARP 以 `Settings Changed` 为由断开隧道。所以本工具把后缀**放在连接之前写**，连上后只做确认，避免白断一次。

**故障安全**：代理一旦挂掉，命中后缀的域名就解析不了（后缀覆盖 com/net/org 等，影响面很大）。所以有守卫线程每 30 秒核对「代理活着 + fallback 服务器仍是 `127.0.0.1` + 后缀还在」，救不回来就**立刻把网卡 DNS 还原成 DHCP**，退化成 WARP 原生行为 —— 宁可不分流，也不能让你断网。程序退出时（包括异常退出）也会自动还原。

### Q2-1. 注入规则的时候网络全断了？
已修复。旧版是「先连上 WARP 再逐条注入」，那 8 分钟里隧道已建立、排除列表却是空的，所有流量（含国内）都被灌进隧道。现在改成**先在断开状态下把规则写好、最后才连接**，并且用配置直写把写入压到毫秒级，整个启用过程网络保持直连，用户无感。详见「二、工作原理 → 规则是怎么写进 WARP 的」。

### Q2-2. 为什么每次打开程序都要重新注入一遍？启动太慢了
已修复，三层：
1. **增量同步**：只补 daemon 里缺的规则，已有的绝不重复写；
2. **停用不再清空规则**：旧版「停用分流」会执行 `tunnel ip reset` 把 5400 条全删掉，所以下次启用必然全量重注。现在停用只断开连接，规则留在 WARP 里，再次启用约 1 秒；要彻底清空请用「一键还原」；
3. **配置直写**：真正需要全量写入时，从 8 分 36 秒降到约 27 秒。

### Q2-3. 我明明退出程序了，为什么它还会自己启动 / 自己动网络？
已修复，两处原因：
1. **残留进程**：如果你是用「直接关掉浏览器标签页」的方式离开，程序其实还在托盘里跑（这是托盘的正常行为，点托盘右键「退出」才是真退出）。现在启动时会检测端口占用，重复双击只会打开已有控制台，不会再多开一个进程。
2. **状态误判**：旧版把 `state.json` 里的 `enabled=true` 当成「现在也开着」，于是新进程一起来就自动重连 WARP、自动注入规则。现在启动后会**先校对 daemon 的真实状态**：
   - daemon 确实连着 → 认定为「分流仍在生效」，正常显示已启用；
   - daemon 没连 → **不擅自动手**，面板提示「上次的分流未自动恢复，点开关即可秒级恢复」，只有你显式打开设置里的 **「启动时自动恢复分流」** 才会自动执行。

### Q3. 前端报「请求失败 / 无法连接本地服务」
- 确认是**双击 `run.bat`** 启动，而不是直接打开 `index.html`；
- 浏览器地址栏必须是 `http://127.0.0.1:8777/`；
- 若系统 / 浏览器走了代理，把 `127.0.0.1` 加入代理「绕过列表」（或临时关闭代理）；
- 用管理员 PowerShell 运行 `netstat -ano | findstr 8777` 看端口是否真的在监听。

### Q4. 端口 8777 被占用？
关闭其它实例，或修改环境变量 `WARP_SPLIT_PORT` 换端口（同时 `run.bat` 里的端口也要一致）。

### Q4-1. Proxy 分路下，游戏 / QUIC / 语音还是不行？
预期行为。Proxy 分路只做 **TCP**（SOCKS5 CONNECT），UDP 不代理。游戏、QUIC、部分语音走 UDP，请切回 **TUN 全局**。这也是两条路并存、而不是用 Proxy 取代 TUN 的原因。

### Q4-2. Proxy 分路下配了代理，但某些国内站反而慢了？
分流判定用「解析出的 IP **全部**落在国内才直连」，否则走代理。若某国内站挂了境外 CDN 节点，会被判成走代理（能打开，但绕了一圈）。可在控制台看「桥接 直连/代理」计数确认实际走向；要强制直连请切回 TUN 全局。

### Q4-3. 开了「写入系统代理」后，公司软件 / 银行插件出问题？
关掉那个开关即可，工具会**精确还原**你原来的代理设置（写入前自动备份）。若怀疑残留，可手动检查
`HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` 的 `ProxyEnable` / `ProxyServer`。

### Q5. 用的是公司 / 团队的 Zero Trust WARP？
若 WARP 被团队策略接管，`tunnel ip add-range`（split-tunnel 排除）可能被策略锁定而报错。
此时请改用团队后台的 Device Profile 配置分流，或联系管理员。个人免费 WARP 不受影响。

### Q6. 规则库是空的 / 更新失败？
`china_cidr.txt` 来自 APNIC（直连可用，无需翻墙）。若点「更新中国IP列表」失败，检查网络是否能访问 `ftp.apnic.net`，或手动下载后覆盖该文件。

### Q7. 托盘图标没出现？
- 确认设置中「系统托盘图标」为开启，且未用 `--no-tray` 启动；
- **Windows 11 默认把新图标折叠进任务栏右下角的「^」隐藏区**，点开「^」即可看到，拖出来可常驻；
- 确认是**最新版**代码：早期版本托盘线程会崩溃（`ctypes.wintypes` 未导入），图标一闪即逝，日志会出现「托盘线程异常」；
- 托盘失败不会影响 Web 控制台，日志里会有相应提示；可查看 `warp_split.log` 是否有「托盘图标已启动」。

### Q8. 开机自启开关点了没反应 / 报错？
开机自启通过 `schtasks` 注册计划任务，需要管理员权限（用 `run.bat` 启动即具备）。
若被安全软件拦截 `schtasks.exe`，请允许该操作；也可改为手动把 `run.bat` 的快捷方式放进
`shell:startup` 目录实现自启（但那样不会自动提权）。

### Q9. 延迟显示「—」或数值偏高？
- 工具会依次尝试 ICMP、TCP 握手、HTTPS 往返三种方式，全部失败才显示 `—`；
- 若你本机禁用了 ICMP（很多网络环境默认禁用），会自动使用 TCP / HTTPS 兜底，属正常；
- 「国内延迟」使用固定在中国大陆 CIDR 内的探测点，确保走直连；若你网络到这些点本身较慢，数值会偏高。

### Q10. 面板提示「Zero Trust 账号锁定」？
说明你的 WARP 由团队 / 组织策略接管（设置里 `Switch Locked` 或包含组织信息），
split-tunnel 排除可能被策略禁止。请改用团队后台的 Device Profile 配置分流，或联系管理员。

### Q11. 关掉分流开关后，网络会受影响吗？
不会。停用就是「撤掉 DNS 接管 → 断开 WARP → 回到纯直连」，你的网络会变回装本工具之前的状态，
停用后程序还会再确认一次确实能上网。分流规则会**保留**在 WARP 配置里（断开状态下不生效），
所以再次启用是秒级的；想彻底清空请用「一键还原」。

### Q12. 程序会不会自己把分流打开？
不会，保障层**只做减法**。看门狗 / 急救 / 系统兜底任务在任何情况下都不会启用分流、
不会注入规则、不会自动重连。急救若不得不断开隧道，会同时摘掉自动重连旗标并把分流
标记为「已暂停」——是否恢复由你决定，面板会明确提示。手动点开关或打开「启动时自动恢复分流」
（默认关）才会启用。

### Q13. 程序没运行 / 被强杀了，网络会不会被它搞坏？
理论上可能被上一版的残留影响（DNS 指向已停止的本地代理），这正是 v1.2.1 修的那类问题。
现在有三道兜底：① 程序启动时自动检测并清理残留；② 程序运行时看门狗每 20 秒探测；
③ **系统计划任务每 5 分钟巡检**（`CloudflareWARP-Split-Guard`），即使程序根本没启动也由系统拉起。
不想用第③道可以在面板「网络保障」里关掉。

### Q14. 「网络保障」里的急救会做什么？会反复折腾吗？
会按代价从小到大逐级退让，每做一步就复查一次，网络通了立刻停止：
① 还原网卡 DNS + 撤掉 fallback 后缀 → ② 断开 WARP 回到直连 → ③ netsh 强制清空网卡 DNS。
自动触发有 **5 分钟跨进程冷却**（主进程和计划任务都遵守），不会反复拆网络；
手动点「立即网络急救」则无视冷却强制执行。

## 九、技术细节

- **后端** `warp_split.py`：纯 Python 标准库实现的 HTTP 服务（端口 `8777`）。
  - 启用流程：`disconnect → mode warp → connect（含重试 / 服务重启兜底）→ 并发 add-range 注入 china_cidr.txt`。
  - 停用 / 还原：`disconnect + tunnel ip reset` 瞬间清空自定义排除。
- **并发注入**：使用线程池（`WARP_SPLIT_WORKERS`，默认 20）并发调用 `warp-cli`，数千条规则约 1–2 分钟完成。
- **状态持久化**：`state.json` 记录开关状态（运行时自动生成，已加入 `.gitignore`）。
- **设置持久化**：`settings.json` 记录主题与各开关（本机配置，已加入 `.gitignore`）。
- **后台守护线程**（随服务启动）：
  | 线程 | 周期 | 职责 |
  |---|---|---|
  | `metrics_loop` | 3s | 国内 / 国际延迟采样、速率实测、历史曲线数据 |
  | `egress_loop` | 30s | 刷新公网出口 IP（独立线程，避免拖慢延迟采样） |
  | `reconnect_loop` | 15s | 断线自动重连守护 |
  | `autoupdate_loop` | 24h | 后台自动更新中国 IP 规则库 |
  | `tray_updater` | 5s | 刷新托盘图标状态 |
- **托盘实现**：零依赖，使用 `ctypes` 直接调用 Win32 `Shell_NotifyIcon` API 创建托盘图标，无需 `pystray` / `PIL` 等第三方库。
- **开机自启**：`schtasks /create /sc onlogon /rl highest` 注册计划任务，无需把程序放进「启动」文件夹，也不会被普通权限限制。
- **环境变量**（可选）：
  | 变量 | 默认 | 说明 |
  |---|---|---|
  | `WARP_SPLIT_PORT` | `8777` | 本地服务端口 |
  | `WARP_SPLIT_WORKERS` | `20` | 并发注入线程数 |
  | `WARP_SPLIT_MAX` | `0`（全部） | 仅注入前 N 条（调试用） |
- **命令行参数**：
  | 参数 | 说明 |
  |---|---|
  | `--no-tray` | 不启动系统托盘图标 |
  | `--tray` | （计划任务使用）正常启动并启用托盘 |

## 十二、卸载

1. 控制台点「一键还原」确保网络干净；
2. 关闭 `run.bat` 打开的页面与后台服务（任务管理器结束 `python.exe` 进程，或 `netstat` 找到 8777 端口进程结束）；
3. 直接删除整个 `Cloudflare WARP` 文件夹即可；
4. （可选）在「应用和功能」中卸载 Cloudflare WARP 客户端。
