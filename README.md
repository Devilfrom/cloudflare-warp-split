# Cloudflare WARP 智能分流控制台

> 国际流量走 Cloudflare WARP 加密出口，国内流量直连 —— 一个零依赖、可视化的 Windows 流量分流工具。

## 一、它能做什么

> 本节每个功能都写清楚两件事：**具体做什么**、**大概怎么实现**。想深入原理的，
> 每个条目都能在「二、工作原理」「八、FAQ」「九、技术细节」里找到展开版。

### 1. 分流核心

**🌍 国际流量走 WARP**
- **具体功能**：访问境外网站 / 服务时，流量经 Cloudflare WARP 隧道加密，从 Cloudflare 边缘节点出口；面板实时显示出口 IP 与边缘节点代号（如 `LAX`）和归属地。
- **实现原理**：用 WARP 官方的 **split-tunnel 排除列表**——命中排除列表的 IP 走直连，未命中的全部流量落入 WARP 全隧道。分流判定在 WARP daemon 内完成，本工具**不拦截、不修改任何数据包**。

**🏠 国内流量直连**
- **具体功能**：中国大陆 IP 走本地网络直连，不绕路、不掉速，国内视频 / 游戏 / 网银完全不受影响。
- **实现原理**：把 APNIC 的中国大陆 IPv4 段（5400+ 条 CIDR）写进 WARP 排除列表；规则来自公开分配数据，可用「更新中国IP列表」一键刷新。

**🧠 智能 DNS 分流（默认开启）**
- **具体功能**：让国内网站解析到**国内 CDN 节点**（实测吞吐提升 2.3 倍、首包快 30 倍），境外域名走公网 DNS 经隧道查询、不被 ISP 污染。这是「开了分流千兆跑不满」的正解。
- **实现原理**：本机 `127.0.0.1:53` 起一个 DNS 代理按域名分流解析，再通过 WARP 官方的 **`dns fallback` 后缀机制**（com / net / org 等）把对应域名交给它——不去争抢网卡 DNS（WARP 虚拟网卡 metric 更低，改网卡 DNS 抢不过，实测调到 50 也没用）。

**🌐 域名级分流**
- **具体功能**：IP 规则（中国 CIDR）管不到"国内服务解析到海外 CDN 节点"的情况——节点不在 CN 段里，流量照样进隧道。域名规则让 daemon 在路由层直接放行这些域名的连接，与 IP 规则互补。面板支持添加 / 删除 / 一键导入 28 个常用国内平台预设，每条规则带「已生效 / 待生效」回查标记。
- **实现原理**：写进 WARP 配置的 `excluded_hosts` 字段（条目格式与 `excluded_ips` 相同）。**不用逐条 CLI**——实测 `tunnel host add` 会触发 daemon "Settings Changed" 直接断开，每条一次断线重连还可能卡死；改为与 IP 规则同走「停服务 → 原子改写 → 起服务」秒级通道，写入后回查 `tunnel host list` 校验。运行中修改约十几秒生效，未启用时仅保存设置。

**🔀 两条分路可切换：TUN 全局 / Proxy 分路**
- **具体功能**：**TUN 全局**（默认）所有进程零配置生效，含 UDP / 游戏；**Proxy 分路**不开 TUN、不改一行系统路由，仅配了代理的应用走分流，经常被 RDP 远程接入的场景零风险。
- **实现原理**：TUN 用 `warp-cli mode warp` 接管系统路由；Proxy 用 `warp-cli mode proxy` + SOCKS5（`127.0.0.1:40000`），外面再叠一层本地 HTTP 分流桥（`127.0.0.1:7890`，纯标准库）：域名解析后用**同一套 CIDR** 判定，国内直连、国外走 WARP SOCKS5。

### 2. 控制与可视化

**🖥️ 可视化控制台**
- **具体功能**：浏览器打开即看运行状态、出口 IP、规则注入数，大开关一键启用 / 停用，所有设置即时生效。
- **实现原理**：后端 `warp_split.py` 用 Python 标准库 `http.server` 在 `127.0.0.1:8777` 起服务，前端每 1.5 秒轮询 `/api/status`；规则数、网卡 DNS、fallback 这些每次拉取都要新起 warp-cli / PowerShell 的高频项**全部带 TTL 缓存**（实测 `/api/status` 从 581ms 降到 197ms）。

**🗺️ 出口拓扑可视化**
- **具体功能**：一张会呼吸的节点图——本机 → 分流引擎 → 国内直连 / WARP 隧道；沿线粒子**流速随该分支延迟变化、密度随 DNS 查询量变化**；点击节点看全部详情（出口 IP、边缘节点、归属地、fallback、桥接统计等）。
- **实现原理**：独立的 `/api/topology` 接口**纯读内存缓存，零子进程、零网络请求**（热调用 0.01ms）；粒子动画用 rAF + 预采样折线（帧内纯数组插值），页面隐藏时整个循环停渲染——**不影响分流性能**。

**📊 实时速率 / 延迟面板**
- **具体功能**：国内延迟、国际延迟、下载速率、在线时长四块磁贴 + 最近约 3 分钟趋势曲线；在线时长本地每秒走表，不等轮询。
- **实现原理**：后台 `metrics_loop` 每 3 秒采样延迟（ICMP → TCP 握手 → HTTPS 三级自动兜底，禁 ICMP 也能出数），约 30 秒实测一次下行吞吐；前端 Canvas 按容器宽度 × devicePixelRatio 重绘，高清屏不发虚。

**📡 WARP 隧道实时状态**
- **具体功能**：隧道延迟 / 丢包率 / 收发流量 / 协议 / 入口端点 / 出口 Colo / TLS 版本 / 后量子加密 / 上次握手时间，一眼看出"WARP 现在活好不好"；仅连接时显示，5 秒刷新。
- **实现原理**：解析 `warp-cli tunnel stats`（一条 0.2 秒的只读命令），单独走 `/api/tunnel_stats` 接口 + 后端 3 秒 TTL 缓存——不并进 `/api/status`，守住那条 145ms 的轮询红线。

**🔔 系统托盘图标**
- **具体功能**：图标颜色反映连接状态（绿 = 分流中 / 橙 = 操作中 / 红 = 未启用），单击或双击打开面板，右键菜单快速启用 / 停用 / 修复 IPv6 / 退出。
- **实现原理**：`ctypes` 直接调用 Win32 `Shell_NotifyIcon` API，**零第三方依赖**（不用 pystray / PIL）。

### 3. 自动化与守护

**🔁 断线自动重连守护**
- **具体功能**：启用状态下 WARP 意外断开，自动重连并补齐差额规则（默认开启，可关）。
- **实现原理**：后台线程每 15 秒检查一次 WARP 状态；重连走**增量同步**（只补 daemon 里缺的规则，已有的绝不重写），所以恢复是秒级的。

**🛡️ 网络保障（底线：任何时候都要能上网）**
- **具体功能**：分流是锦上添花，上网才是刚需。看门狗每 20 秒探测联网，连续失败即**自动逐级退让**（还原网卡 DNS → 断开 WARP 回直连 → 强制清空 DNS）；另有**系统兜底计划任务**每 5 分钟巡检，程序被强杀或没启动时，也能兜住「DNS 残留导致全机断网」。控制台与托盘都有「网络急救」可立即手动触发。
- **实现原理**：一层与分流状态完全无关的看门狗 + `schtasks` 注册的一次性巡检任务（`--guard` 模式）；每级退让后复查，通了立刻停；自动触发有 **5 分钟跨进程冷却**（写进 `state.json`，主进程和计划任务共享），不会反复拆网络；**只做减法**——任何情况下都不会自动开启分流（已用 AST 静态校验）。

**🚀 开机自启**
- **具体功能**：登录时以管理员权限自动启动本工具（默认关，面板可开）。
- **实现原理**：`schtasks /create /sc onlogon /rl highest` 注册计划任务——不进「启动」文件夹，也不受普通权限限制。

**📡 规则库自更新**
- **具体功能**：一键从 APNIC 拉取最新中国大陆 IP 分配；也可开启后台每 24 小时自动更新。
- **实现原理**：直连抓取 APNIC 分配文件，本地生成 CIDR；自动更新跑在后台线程里，热更新时保留你已启用的自定义列表。

### 4. 工具与辅助

**🩺 分流自检**
- **具体功能**：一键验证「国际是否走 WARP、国内是否直连」，输出 PASS / FAIL 和 5 项明细，不再靠猜。
- **实现原理**：查 WARP 连接态、出口 IP 归属、规则注入数，并 traceroute 一个中国 IP 和一个外国 IP——第一跳是本地网关 = 直连，第一跳是 Cloudflare = 走了 WARP。

**🛡️ 网络体检（IP/DNS 污染检测）**
- **具体功能**：一键回答四个问题——**IP 有没有被污染**、出口归属是否正常、两条链路通不通、分流有没有生效。输出 0–100 评分与三态总评（健康 / 需关注 / 有风险），每个探测域名把「系统解析 / DoH 基准 / 上游直查」三条通道拿到的 IP 并列展示，一眼看出谁在撒谎。
- **实现原理**：对 google / youtube / facebook / wikipedia 四个境外域名 + 百度（国内对照），分别问三条通道——系统解析（跟随网卡 DNS，WARP 连着时即 WARP DNS）、DoH 基准（cloudflare-dns.com，经隧道出境）、**上游直查**（对路由器 / 运营商 DNS 发原始 UDP 查询，绕过 WARP 看真实网络）。判定用双保险：命中已知伪造 IP 网段库（31.13.92.0/24、37.61.224.0/20 等 20+ 网段）即标记「已污染」；网段库没收录的靠**分歧检测**兜底（上游与 DoH 基准不一致、或上游 NXDOMAIN 而 DoH 有结果，即标记「疑似污染」）。全程只读，不改任何配置。

**🔧 修复 IPv6**
- **具体功能**：解决 WARP 连接卡在 `happy eyeballs` 连不上的问题（可逆，再点一次恢复）。
- **实现原理**：禁用 `CloudflareWARP` 虚拟适配器的 IPv6（PowerShell / netsh），让 daemon 只走 IPv4 端点完成握手。

**🔘 一键开关 / 一键还原**
- **具体功能**：随时启用、停用；任何异常点「一键还原」立刻回到最干净的网络状态。
- **实现原理**：**停用只断开、不清规则**（规则留在 WARP 配置里，再次启用约 1 秒）；只有「一键还原」才执行 `tunnel ip reset` 彻底清空。启用顺序恒为「断开 → 写好规则和 DNS → 最后才连接」，注入期间网络保持直连、用户无感。

**🗂️ 自定义 / 多规则列表导入**
- **具体功能**：除内置中国列表外，可粘贴文本或填 URL 导入自己的 CIDR 列表，与内置列表合并注入，每个列表可单独启用 / 停用 / 删除。
- **实现原理**：自定义列表存在 `rules/` 目录（已 gitignore），注入时与 `china_cidr.txt` 合并去重后走同一条写入通道。

**🏢 Zero Trust 账号锁定提示**
- **具体功能**：检测到 WARP 被团队策略接管（split-tunnel 可能被锁）时，面板顶部给出醒目提示与处理建议。
- **实现原理**：解析 `warp-cli settings` 里的组织 / 锁定字段。

**🌓 暗亮主题切换**
- **具体功能**：深色 / 浅色主题一键切换，选择自动保存。
- **实现原理**：整套配色用 CSS 变量定义，切换只改 `<html data-theme>` 一个属性；选择写进 `settings.json`。

## 二、工作原理

```
                        你的电脑
┌──────────────────────────────────────────────┐
│                                                │
│   国内流量 (中国大陆 IP)  ────►  本地网关  ──────┼──► 直连（不走 WARP）
│                                                │
│   国际流量 (其余所有 IP) ──►  Cloudflare WARP   ┼──► 加密隧道 ──► Cloudflare 出口
│                          (split-tunnel 排除)   │
└──────────────────────────────────────────────┘
```

工具把 **中国 IPv4 段**加入 WARP 的 **split-tunnel 排除列表（exclude）**：

- 命中排除列表（中国大陆）→ 直连本地网络；
- 未命中（国际）→ 走 WARP 全隧道出口。

这是 WARP 官方能力，比手工改系统路由表更干净、更易还原。

### 规则是怎么写进 WARP 的（性能关键）

早期版本用 `warp-cli tunnel ip add-range` 一条一条写规则，而 WARP 的 daemon 是**串行**处理这些请求的（实测 74 ms/条），5400+ 条要 **8 分 36 秒**。更糟的是旧流程是「先把 WARP 连上，再逐条注入」——这 8 分钟里隧道已经建立、但排除列表几乎是空的，于是**包括国内流量在内的所有流量都被灌进隧道**，表现为「一注入就断网」。

现在改成两条：

1. **配置直写（秒级）**：WARP 把排除列表以明文 JSON 存在
   `C:\ProgramData\Cloudflare\settings.json` 的 `excluded_ips` 里。
   停掉 `CloudflareWARP` 服务 → 原子改写该文件 → 起服务，daemon 就按新配置加载。
   实测写入 5400+ 条耗时 **0.007 秒**。改写照抄 daemon 自带的默认排除（Apple 服务、组播、链路本地等 22 条），只替换我们自己的部分；改写前自动备份，失败自动回退逐条注入。
2. **先注入、后连接**：注入在 WARP **断开状态**下完成，此时网络是纯直连，用户在启用过程中完全无感；规则全部就位后才执行 `connect`，一步到位。

| 场景 | 旧版 | 现在 |
|---|---|---|
| 全新启用（规则为空） | 516 秒 | **约 27 秒** |
| 停用后再启用（规则已在） | 516 秒 | **约 16 秒**（仅剩 WARP 握手时间） |

另外「停用分流」现在**只断开、不清规则**（旧版会 `tunnel ip reset`），所以再次启用是秒级的。需要彻底清空请用「一键还原」。

### 两条分路：TUN 全局 / Proxy 分路（不开 TUN）

上面讲的是 **TUN 路线**。从 v1.1 起还有第二条路 —— **Proxy 分路**，在控制台「分路模式」里切换。

为什么要做第二条路：TUN 会接管系统默认路由。如果你**经常被 RDP 远程接入**，隧道一抖动，远程桌面就断在门外、人进不去。Proxy 分路一行系统路由都不改。

它不需要自己写分流桥 —— 本机 `warp-cli`（2026.6.x）原生就支持：

```
warp-cli mode proxy          # 建隧道供 SOCKS5 使用，不创建 TUN 适配器
warp-cli proxy port 40000    # 指定 SOCKS5 监听端口 127.0.0.1:40000
```

实测（`tools/test_proxy_mode.py`）：切到 proxy 模式后 **CloudflareWARP 适配器根本不存在、WARP 接口路由 0 条**，裸直连 `cdn-cgi/trace` 显示 `warp=off` —— 系统路由一行未改。

但裸 SOCKS5 **不分流**：你给浏览器配上它，国内站也要绕地球一圈。所以再叠一层本地 HTTP 分流桥 `127.0.0.1:7890`（纯 Python 标准库，已打进 exe）：目标域名解析后用同一套 5440 条 CIDR 判定，国内直连、国外走 WARP SOCKS5。

| | TUN 全局（默认） | Proxy 分路 |
|---|---|---|
| 生效范围 | 所有进程，零配置 | 仅配了代理的应用（浏览器 / git / curl） |
| 系统默认路由 | 接管 | **完全不动** |
| RDP / 局域网 | 靠 `ALWAYS_DIRECT` 保留段兜底 | **零影响** |
| UDP / QUIC / 游戏 | 支持 | 不支持（SOCKS5 只做 TCP） |
| 隧道异常的后果 | 全局断网 | 只有代理不可用，本机网络照常 |
| 分流判据 | IP 段（5440 条 CIDR） | 同一套 CIDR，域名解析后判定 |

使用方法：

1. 控制台「分路模式」切到 **Proxy 分路**，点开关启用；
2. 给应用配上代理 `127.0.0.1:7890`（HTTP）或直接用 `127.0.0.1:40000`（SOCKS5，不分流）；
   ```bash
   git config --global http.proxy http://127.0.0.1:7890
   set HTTPS_PROXY=http://127.0.0.1:7890     # cmd
   $env:HTTPS_PROXY="http://127.0.0.1:7890"  # PowerShell
   ```
3. 想让不认 SOCKS 的普通应用也走分流，打开「写入系统代理」开关（默认关）。
   局域网与 localhost 会自动写进 `ProxyOverride` 绕过，关闭时精确还原你原来的值。

已知限制：UDP 不代理（游戏 / QUIC 请切回 TUN）；分流桥是用户态 Python，适合网页 / git / 包管理器，不适合大流量下载或视频。

## 四、Cloudflare WARP 安装与配置（详细）

### 1. 下载客户端

前往 Cloudflare 官方页面下载 **Cloudflare WARP（即 1.1.1.1 客户端）** 的 Windows 版本：

- 官网入口：<https://one.one.one.one/> → 点击 **Download for Windows**
- 或 Cloudflare 产品页：<https://www.cloudflare.com/products/warp/>
- **官方直链（GA 稳定版，x64）**：<https://downloads.cloudflareclient.com/v1/download/windows/ga>

> 本仓库的 **GitHub Release** 附件里也附了一份安装包镜像，方便网络受限时
> 直接取用。但仍建议优先走官方渠道，并以官方校验值为准。

> 安装后默认路径为 `C:\Program Files\Cloudflare\Cloudflare WARP\`，包含：
> - `Cloudflare WARP.exe`（图形客户端）
> - `warp-cli.exe`（命令行工具，本工具依赖它）

### 2. 安装

双击下载的安装包，按向导一路「下一步」完成安装。安装后任务栏右下角会出现 Cloudflare WARP 图标。

### 3. 登录 / 激活（可选但建议）

- 打开 Cloudflare WARP 客户端，默认即为 **WARP** 模式。
- 点击登录可绑定免费账号（**WARP 基础模式免费，无需付费**；WARP+ 需要邀请密钥，非必需）。
- 即使是完全不登录的匿名状态，基础 WARP 模式通常也能连接。

### 4. 验证安装

以**管理员**身份打开 PowerShell，执行：

```powershell
# 查看版本（能输出版本号即说明安装成功）
```

## 八、常见问题（FAQ）

### Q1. 点启用报 `Connecting ... happy eyeballs ...` 卡住 / 启用失败
这是 WARP 守护进程在同时探测 IPv4 / IPv6 端点，IPv6 探测卡住导致握手完不成。
**解决**：
1. 工具已内置「断开重连重试 4 次 + 重启 `CloudflareWARP` 服务兜底」，多数情况会自动恢复；
2. 若仍失败，点控制台的 **「修复IPv6」** 按钮禁用适配器 IPv6 后再启用；
3. 或在「网络连接 → CloudflareWARP 适配器 → 属性」取消 IPv6 勾选。

### Q2. 启用分流后，千兆宽带为什么跑不满？（这是 DNS 的问题，不是路由的问题）

**根因**：开了 WARP 之后，DNS 查询会经隧道出境。国内 CDN 看到的是 Cloudflare 的海外出口（`colo=LAX`），于是把你当境外用户，返回**海外节点**。

实测同一台机、同一个国内镜像、同一个文件：

| 域名被解析到 | 吞吐（8 并发） | 首包延迟 |
|---|---|---|
| 海外节点 `101.33.20.158`（新加坡） | 80 Mbps | 2.42s |
| 国内节点 `120.232.191.137` | **183 Mbps** | **0.08s** |

RTT 差 30 倍。TCP 单流吞吐上限 ≈ 窗口/RTT，所以延迟一高，带宽就上不去 —— 哪怕规则本身分得再准也没用。

典型表现（开了分流后）：

| 域名 | WARP 的 DNS 返回 | 国内 DNS 返回 |
|---|---|---|
| www.baidu.com | `103.235.46.x`（海外） | `111.45.11.x` ✅ |
| www.taobao.com | `155.102.176.x`（海外） | `120.240.158.x` ✅ |
| mirrors.cloud.tencent.com | `101.33.20.x`（新加坡） | `120.232.191.x` ✅ |

**解决办法：开「智能 DNS 分流」**（默认开启）。它在本机 `127.0.0.1:53` 起一个 DNS 代理，按域名做分流解析：国内域名用国内 DNS 拿国内节点，境外域名走公网 DNS 经隧道查询。

实现上用的是 WARP **官方的 `dns fallback` 机制**（`warp-cli dns fallback add <后缀>`），而不是去争抢网卡 DNS —— 因为 WARP 的虚拟网卡 metric 更低，改网卡 DNS 根本抢不过它（实测把 metric 调到 50 也没用）。

### Q2-0. 智能 DNS 的原理细节（为什么这么绕）
有三个反直觉的实测结论，都踩过坑：
1. WARP 的 fallback 服务器**默认不是** `127.0.0.1`，而是网卡 DHCP 学来的地址（通常是路由器）。只加后缀不改网卡 DNS 的话，查询会转给路由器，国内域名碰巧是对的，但**境外域名会被 ISP 污染**（实测 `google.com` 被解析成 `31.13.92.37`，那是 Facebook 的段）。
2. WARP 的 fallback 服务器**会跟随网卡 DNS**，但**只在网卡 DNS 是单条目时**才跟随（实测写两条 `127.0.0.1`+`223.5.5.5` 会失效退回路由器）。所以只写一条 `127.0.0.1`。
3. **境外分支绝不能填 `127.0.2.2`（WARP 自带 DNS）**，否则死循环：代理问 `127.0.2.2` 查 `google.com` → WARP 发现 `com` 命中 fallback 后缀 → 把查询转回 `127.0.0.1`（我们）→ 我们再问 `127.0.2.2` → …，实测 3.5 秒超时后只能退回被污染的国内结果。改用公网 DNS（`1.1.1.1`，经隧道出境）即可绕开。

另外 `dns fallback add/reset` 属于「设置变更」，会让 WARP 以 `Settings Changed` 为由断开隧道。所以本工具把后缀**放在连接之前写**，连上后只做确认，避免白断一次。

**故障安全**：代理一旦挂掉，命中后缀的域名就解析不了（后缀覆盖 com/net/org 等，影响面很大）。所以有守卫线程每 30 秒核对「代理活着 + fallback 服务器仍是 `127.0.0.1` + 后缀还在」，救不回来就**立刻把网卡 DNS 还原成 DHCP**，退化成 WARP 原生行为 —— 宁可不分流，也不能让你断网。程序退出时（包括异常退出）也会自动还原。

### Q2-1. 注入规则的时候网络全断了？
已修复。旧版是「先连上 WARP 再逐条注入」，那 8 分钟里隧道已建立、排除列表却是空的，所有流量（含国内）都被灌进隧道。现在改成**先在断开状态下把规则写好、最后才连接**，并且用配置直写把写入压到毫秒级，整个启用过程网络保持直连，用户无感。详见「二、工作原理 → 规则是怎么写进 WARP 的」。

### Q2-2. 为什么每次打开程序都要重新注入一遍？启动太慢了
已修复，三层：
1. **增量同步**：只补 daemon 里缺的规则，已有的绝不重复写；
2. **停用不再清空规则**：旧版「停用分流」会执行 `tunnel ip reset` 把 5400 条全删掉，所以下次启用必然全量重注。现在停用只断开连接，规则留在 WARP 里，再次启用约 1 秒；要彻底清空请用「一键还原」；
3. **配置直写**：真正需要全量写入时，从 8 分 36 秒降到约 27 秒。

### Q2-3. 我明明退出程序了，为什么它还会自己启动 / 自己动网络？
已修复，两处原因：
1. **残留进程**：如果你是用「直接关掉浏览器标签页」的方式离开，程序其实还在托盘里跑（这是托盘的正常行为，点托盘右键「退出」才是真退出）。现在启动时会检测端口占用，重复双击只会打开已有控制台，不会再多开一个进程。
2. **状态误判**：旧版把 `state.json` 里的 `enabled=true` 当成「现在也开着」，于是新进程一起来就自动重连 WARP、自动注入规则。现在启动后会**先校对 daemon 的真实状态**：
   - daemon 确实连着 → 认定为「分流仍在生效」，正常显示已启用；
   - daemon 没连 → **不擅自动手**，面板提示「上次的分流未自动恢复，点开关即可秒级恢复」，只有你显式打开设置里的 **「启动时自动恢复分流」** 才会自动执行。

### Q3. 前端报「请求失败 / 无法连接本地服务」
- 确认是**双击 `run.bat`** 启动，而不是直接打开 `index.html`；
- 浏览器地址栏必须是 `http://127.0.0.1:8777/`；
- 若系统 / 浏览器走了代理，把 `127.0.0.1` 加入代理「绕过列表」（或临时关闭代理）；
- 用管理员 PowerShell 运行 `netstat -ano | findstr 8777` 看端口是否真的在监听。

### Q4. 端口 8777 被占用？
关闭其它实例，或修改环境变量 `WARP_SPLIT_PORT` 换端口（同时 `run.bat` 里的端口也要一致）。

### Q4-1. Proxy 分路下，游戏 / QUIC / 语音还是不行？
预期行为。Proxy 分路只做 **TCP**（SOCKS5 CONNECT），UDP 不代理。游戏、QUIC、部分语音走 UDP，请切回 **TUN 全局**。这也是两条路并存、而不是用 Proxy 取代 TUN 的原因。

### Q4-2. Proxy 分路下配了代理，但某些国内站反而慢了？
分流判定用「解析出的 IP **全部**落在国内才直连」，否则走代理。若某国内站挂了境外 CDN 节点，会被判成走代理（能打开，但绕了一圈）。可在控制台看「桥接 直连/代理」计数确认实际走向；要强制直连请切回 TUN 全局。

### Q4-3. 开了「写入系统代理」后，公司软件 / 银行插件出问题？
关掉那个开关即可，工具会**精确还原**你原来的代理设置（写入前自动备份）。若怀疑残留，可手动检查
`HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` 的 `ProxyEnable` / `ProxyServer`。

### Q5. 用的是公司 / 团队的 Zero Trust WARP？
若 WARP 被团队策略接管，`tunnel ip add-range`（split-tunnel 排除）可能被策略锁定而报错。
此时请改用团队后台的 Device Profile 配置分流，或联系管理员。个人免费 WARP 不受影响。

### Q6. 规则库是空的 / 更新失败？
`china_cidr.txt` 来自 APNIC（直连可用，无需翻墙）。若点「更新中国IP列表」失败，检查网络是否能访问 `ftp.apnic.net`，或手动下载后覆盖该文件。

### Q7. 托盘图标没出现？
- 确认设置中「系统托盘图标」为开启，且未用 `--no-tray` 启动；
- **Windows 11 默认把新图标折叠进任务栏右下角的「^」隐藏区**，点开「^」即可看到，拖出来可常驻；
- 确认是**最新版**代码：早期版本托盘线程会崩溃（`ctypes.wintypes` 未导入），图标一闪即逝，日志会出现「托盘线程异常」；
- 托盘失败不会影响 Web 控制台，日志里会有相应提示；可查看 `warp_split.log` 是否有「托盘图标已启动」。

### Q8. 开机自启开关点了没反应 / 报错？
开机自启通过 `schtasks` 注册计划任务，需要管理员权限（用 `run.bat` 启动即具备）。
若被安全软件拦截 `schtasks.exe`，请允许该操作；也可改为手动把 `run.bat` 的快捷方式放进
`shell:startup` 目录实现自启（但那样不会自动提权）。

### Q9. 延迟显示「—」或数值偏高？
- 工具会依次尝试 ICMP、TCP 握手、HTTPS 往返三种方式，全部失败才显示 `—`；
- 若你本机禁用了 ICMP（很多网络环境默认禁用），会自动使用 TCP / HTTPS 兜底，属正常；
- 「国内延迟」使用固定在中国大陆 CIDR 内的探测点，确保走直连；若你网络到这些点本身较慢，数值会偏高。

### Q10. 面板提示「Zero Trust 账号锁定」？
说明你的 WARP 由团队 / 组织策略接管（设置里 `Switch Locked` 或包含组织信息），
split-tunnel 排除可能被策略禁止。请改用团队后台的 Device Profile 配置分流，或联系管理员。

### Q11. 关掉分流开关后，网络会受影响吗？
不会。停用就是「撤掉 DNS 接管 → 断开 WARP → 回到纯直连」，你的网络会变回装本工具之前的状态，
停用后程序还会再确认一次确实能上网。分流规则会**保留**在 WARP 配置里（断开状态下不生效），
所以再次启用是秒级的；想彻底清空请用「一键还原」。

### Q12. 程序会不会自己把分流打开？
不会，保障层**只做减法**。看门狗 / 急救 / 系统兜底任务在任何情况下都不会启用分流、
不会注入规则、不会自动重连。急救若不得不断开隧道，会同时摘掉自动重连旗标并把分流
标记为「已暂停」——是否恢复由你决定，面板会明确提示。手动点开关或打开「启动时自动恢复分流」
（默认关）才会启用。

### Q13. 程序没运行 / 被强杀了，网络会不会被它搞坏？
理论上可能被上一版的残留影响（DNS 指向已停止的本地代理），这正是 v1.2.1 修的那类问题。
现在有三道兜底：① 程序启动时自动检测并清理残留；② 程序运行时看门狗每 20 秒探测；
③ **系统计划任务每 5 分钟巡检**（`CloudflareWARP-Split-Guard`），即使程序根本没启动也由系统拉起。
不想用第③道可以在面板「网络保障」里关掉。

### Q14. 「网络保障」里的急救会做什么？会反复折腾吗？
会按代价从小到大逐级退让，每做一步就复查一次，网络通了立刻停止：
① 还原网卡 DNS + 撤掉 fallback 后缀 → ② 断开 WARP 回到直连 → ③ netsh 强制清空网卡 DNS。
自动触发有 **5 分钟跨进程冷却**（主进程和计划任务都遵守），不会反复拆网络；
手动点「立即网络急救」则无视冷却强制执行。

### Q15. 换了新版本 exe，重启后面板没有新功能？
历史上这条链上踩过四个坑，v1.5.1 起全部堵死：

1. **旧进程没退**（v1.4.1 修）：双击新 exe 时旧版本进程还在后台跑，单实例
   检测发现端口被占，只会打开旧实例的控制台然后退出，新 exe 根本没启动。
2. **浏览器聚焦旧标签页**（v1.4.3 修，最隐蔽）：哪怕新 exe 正常启动了，
   双击时程序调 `webbrowser.open()`，浏览器发现同一个 URL 的标签页已存在，
   **只是聚焦它、不重新加载**。若那个标签页是几小时前打开的，里面跑的是
   旧版面板代码，没有版本自检逻辑，永远发现不了自己已过期。
3. **浏览器不刷新**（v1.4.1 修）：面板发现磁盘上有更新版本时弹「立即刷新」
   提示条，5s 自动刷新；v1.5.1 起提示条还可手动关闭（×，本标签页不再提示）。
4. **提示条自己永远可见**（v1.5.1 修，最坑）：v1.4.1 起提示条的样式
   `.panel-update-bar{display:flex;…}` 写在工具类 `.hidden{display:none}`
   **之后**，同特异性后者胜出——class 里有 `hidden`，计算样式却是 `flex`，
   提示条**与版本无关地一直挂在页面底部**。此前每轮验证只查了 class 没查
   计算样式，所以连错四轮。现在 `.hidden` 带 `!important`，冒烟测试直接断言
   三态的计算样式。

**现在的机制**：① 启动时检测到运行中的是旧实例会弹窗明确告知；
② exe 旁的旧面板副本按版本标记自动更新（旧的备份为 `index.user-<版本>.html`）；
③ 打开控制台的 URL 带 exe 构建指纹（`?_b=<mtime>-<size>`），每个版本的
URL 都不同，浏览器必然新建标签页拉取最新面板；④ 面板 header 常驻显示
**版本徽标**（`面板 vX.Y.Z`），一眼可辨当前标签页新旧；⑤ 万一还有旧标签页
活着，版本提示条 5s 后自动刷新。

**如果现在还是没更新**：看面板右上角的版本徽标是不是最新版；不是的话在
那个标签页上按 `Ctrl+F5` 强制刷新一次即可（只此一次，之后全部自动）。

## 九、技术细节

- **后端** `warp_split.py`：纯 Python 标准库实现的 HTTP 服务（端口 `8777`）。
  - 启用流程（TUN 分路，**顺序是关键**）：`disconnect → mode warp → 写入排除规则 → 写入 DNS fallback 后缀 → connect（含重试 / 服务重启兜底）`。
    注入在断开状态完成，此时网络是纯直连，用户无感；规则齐了才连接，一步到位。
  - 规则写入双通道：**直写（默认）**——停 `CloudflareWARP` 服务 → 原子改写
    `C:\ProgramData\Cloudflare\settings.json` 的 `excluded_ips` → 起服务，5400+ 条 **0.007 秒**；
    直写不可用（找不到配置文件 / 权限异常）时**自动回退**逐条 `warp-cli tunnel ip add-range`。
  - 增量同步：重复启用只补差集（回查校验），已有的绝不重写。
  - 停用 = 只 `disconnect`（规则保留，秒级再启用）；一键还原才 `tunnel ip reset` 彻底清空。
- **状态持久化**：`state.json` 记录开关状态与跨进程共享的急救冷却（运行时自动生成，已加入 `.gitignore`）。
- **设置持久化**：`settings.json` 记录主题与各开关（本机配置，已加入 `.gitignore`）。
- **可视化数据接口**：`/api/status`（1.5s 轮询，高频项全带 TTL 缓存；含 `panel_ver` 面板资源版本，
  前端据此在面板文件被换新时弹刷新提示）、`/api/metrics`（3s）、
  `/api/topology`（3s，**纯读内存缓存，零子进程零请求**，出口拓扑图专用）。
- **面板资源自动更新**：`index.html` 头部带 `<!-- warp-split-res vX.Y.Z -->` 版本标记，
  exe 启动时（`ensure_data_files()`）比对 exe 旁副本与内置版本——旧版备份为
  `index.user-<版本>.html` 后自动覆盖，杜绝「换了 exe 面板还是旧的」。
  数据文件（china_cidr 等）仍只做「不存在才复制」，用户刷新过的数据绝不被覆盖。
- **已知坑（v1.4.2 修复）**：`Get-NetRoute` 在某些机器（WARP 虚拟适配器 +
  5400+ 条排除规则的路由表）上每次必挂满超时——**读网卡 DNS 千万别和查网关
  耦合在同一次 PowerShell 调用里**，且持锁期间绝不调可能起子进程的函数。
  网关查询已改用 `netsh interface ipv4 show route`（原生 exe，0.7s）。
- **体检接口**：`/api/audit`（POST，用户手动触发，约 5–12s，结果缓存 30s 防连点）。
  纯只读探测：多域名三通道 DNS 对比（系统解析 / DoH / 对上游 DNS 的原始 UDP 查询）、
  TCP 握手、traceroute；WARP 状态与出口信息复用 `topology_snapshot` 的缓存，
  不额外起 warp-cli 子进程。系统解析一律走线程 `join(2.5)` 限时
  （`getaddrinfo` 不受 socket 超时控制，DNS 卡死时不能把体检本身拖死）。
- **隧道状态接口**：`/api/tunnel_stats`（GET，解析 `warp-cli tunnel stats`，
  后端 3s TTL 缓存，面板 5s 轮询）。刻意不并进 `/api/status`——那条接口有
  145ms 的延迟红线，而 tunnel stats 要新起一个 warp-cli 进程。
- **域名分流接口**：`/api/hosts`（GET 回查列表 / POST 增删清空导入预设）。
  域名规则与 IP 规则同走「停服务 → 原子改写 settings.json → 起服务」秒级通道
  （`excluded_hosts` 与 `excluded_ips` 同文件同格式）；**禁用逐条 CLI**——
  `tunnel host add` 会触发 "Settings Changed" 直接断开 daemon（实测）。
- **后台守护线程**（随服务启动）：
  | 线程 | 周期 | 职责 |
  |---|---|---|
  | `metrics_loop` | 3s | 国内 / 国际延迟采样、速率实测、历史曲线数据 |
  | `egress_loop` | 30s | 刷新公网出口 IP（独立线程，避免拖慢延迟采样） |
  | `self_heal_loop` | 3s | 探测连续失败时自动重连并同步规则；反复无效自动还原为直连 |
  | `reconnect_loop` | 15s | 断线自动重连守护（只补差集规则） |
  | `dns_guard_loop` | 30s | 核对智能 DNS 三件套（代理活着 / fallback 仍是 127.0.0.1 / 后缀还在），救不回立刻还原网卡 DNS |
  | `net_guard_loop` | 20s | 联网探测，连续两次失败触发分级退让（与分流是否启用无关） |
  | `autoupdate_loop` | 24h | 后台自动更新中国 IP 规则库 |
  | `tray_updater` | 5s | 刷新托盘图标状态 |
- **系统兜底任务**：`schtasks` 注册的一次性巡检任务 `CloudflareWARP-Split-Guard`，每 5 分钟以
  `--guard` 模式拉起程序自身——程序没运行 / 被强杀时，由它清理 DNS 残留、恢复联网。
  正常时静默退出，不写日志、不弹窗。
- **托盘实现**：零依赖，使用 `ctypes` 直接调用 Win32 `Shell_NotifyIcon` API 创建托盘图标，无需 `pystray` / `PIL` 等第三方库。
- **开机自启**：`schtasks /create /sc onlogon /rl highest` 注册计划任务，无需把程序放进「启动」文件夹，也不会被普通权限限制。
- **环境变量**（可选）：
  | 变量 | 默认 | 说明 |
  |---|---|---|
  | `WARP_SPLIT_PORT` | `8777` | 本地服务端口 |
  | `WARP_SPLIT_WORKERS` | `20` | 逐条注入回退路径的并发线程数 |
  | `WARP_SPLIT_MAX` | `0`（全部） | 仅注入前 N 条（调试用） |
- **命令行参数**：
  | 参数 | 说明 |
  |---|---|
  | `--no-tray` | 不启动系统托盘图标 |
  | `--tray` | （计划任务使用）正常启动并启用托盘 |
  | `--guard` | 一次性巡检模式：正常时静默退出；发现 DNS 残留 / 断网则执行分级退让（系统兜底任务调用） |

## 十一、安全与隐私

- 所有流量策略都由你本机的 `warp-cli` 执行，**不会上传任何数据到第三方**。
- 国际流量经 Cloudflare WARP 出口，出口 IP 属于 Cloudflare，属正常 VPN / 隧道行为。
- 停用 / 一键还原后，所有自定义规则被清空，网络回到系统默认状态（直连）。
- 规则库仅包含公开的中国大陆 IP 分配信息（APNIC），不含任何个人数据。

## 十二、卸载

1. 控制台点「一键还原」确保网络干净；
2. 关闭 `run.bat` 打开的页面与后台服务（任务管理器结束 `python.exe` 进程，或 `netstat` 找到 8777 端口进程结束）；
3. 直接删除整个 `Cloudflare WARP` 文件夹即可；
4. （可选）在「应用和功能」中卸载 Cloudflare WARP 客户端。
